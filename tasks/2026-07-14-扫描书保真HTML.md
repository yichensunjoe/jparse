# 2026-07-14 扫描书保真 HTML

## 问题

513 页《熔盐堆科学技术导论》为纯扫描 PDF，没有文字层。LiteParse 2.4.0 的无 OCR Markdown 每页只有带 `text` 语言标记的空代码围栏，旧文字统计却把语言标签 `text` 计为 4 个字符，513 页累计为 2052，因此误判为“快速文字层足够”。旧 HTML 只剩 513 个空代码块。

即使强制 LiteParse OCR，复杂图表、设备标注和多栏内容也会被误识成表格或打乱阅读顺序，不适合作为扫描书的可见版面。

## 改动

- 修正文字层评分：排除 Markdown 围栏、图片引用和 HTML 标签，空扫描页现在得分为 0。
- 新增扫描书自动路由：无文字层且页数达到门槛时，不再用 OCR 重排可见正文。
- 新增 `src/scan_html_renderer.py`：用本地 Poppler 以 120 DPI / JPEG 68 生成原页图，逐页 Base64 流式写入单文件 HTML。
- 用本地 Tesseract `chi_sim+eng` / PSM 3 生成每页折叠辅助文字；它仅用于搜索和复制，不影响原页显示。
- HTML 无 JavaScript、无外部资源、无 LLM，使用 CSP、输入转义、图片懒加载、固有尺寸与一页对一页打印样式。
- 页图和渲染结果先写项目 `processing/` 临时区，完成后原子发布并清理临时文件。

## 验证

- 12 项单元测试通过，包括空围栏评分、扫描书自动路由、Base64 页图和 OCR 转义。
- 封面、第 20、100、300、500 页组成的 5 页真实小样端到端生成成功：5 页图、5 个 OCR 辅助层、零外部资源、零脚本，耗时约 4 秒。
- 整本后台自动处理成功：513 页图、513 个 OCR 辅助层，输出 130.9 MB，耗时 374.8 秒，失败 0。
- 将最终 HTML 重新打印得到 513 页 A4，确认 PDF 一页对应 HTML 一页。
- 视觉抽查最终 HTML 第 1、20、100、300、500 页：封面、统计图、DRACS 标注图、四联曲线和后段正文均完整清晰，无重排、拆分或错位。
- 后台监控保持 `PPID=1`，待处理 0、失败 0，`processing/` 无残留临时产物。
