# 2026-07-14 默认 HTML 与图片内嵌

## 目标

将新 PDF 的默认输出从 Markdown 改为排好版的 HTML，同时提取 LiteParse 可识别的 PDF 内嵌图片。运行时不调用 LLM。

## 实现

- `config.json` 的 `output_format` 默认改为 `html`。
- LiteParse 仍只解析一次并生成临时 Markdown，避免为不同输出重复解析 PDF。
- 新增纯 Python 标准库渲染器，支持标题、列表、表格、引用、代码、安全链接、响应式 CSS 与打印 CSS。
- LiteParse 使用 `image-mode=embed`，提取图片在临时目录中落盘，渲染器将其 Base64 嵌入 HTML 后清理临时文件。
- 转义 PDF 中的原始 HTML，只允许 `http`、`https`、`mailto` 和页内锚点链接。
- 旧 `.md` 保留；使用既有 PDF 的单次 LiteParse 结果非破坏性生成了同名 `.html`。

## 验证

- 6/6 单元测试通过：HTML、表格、Base64 图片、OCR 回退、同名保护、危险内容转义。
- 真实通知 PDF 提取 1 张印章 PNG，最终 HTML 包含 1 个 `data:image/png;base64` 图片。
- 纯扫描页触发 OCR 并生成 HTML；LiteParse 未将整页扫描底图作为独立图片返回。
- 后台实际投递 `html-background-e2e.pdf`，只生成 `.html`，完整匹配 `PDF-AUTO-240`。
- HTML 使用 Quick Look 实际渲染预览，中文字形、标题、段落和印章均正常。
- 监控进程从 Terminal GUI 重启并保持 `PPID=1`。
