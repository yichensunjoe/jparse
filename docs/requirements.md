# P052-LiteParse-PDF自动识别 — 需求与范围

## 用户意图

在 macOS 本机提供一个低操作成本的 PDF 投递箱：文件写入稳定后自动处理，同时输出便于阅读的单文件 HTML 和便于 Agent 检索的 Markdown，并归档原 PDF。

## 范围

- 只处理 `inbox/` 中的 PDF，忽略其他文件。
- 对有文字层、短扫描件和长篇扫描书选择确定性路由。
- 提取可识别位图；HTML 以 data URI 内嵌，Markdown 使用相对资源目录。
- 保守修复软换行和强信号表格缺列问题。
- 成功归档到 `processed/`，失败移入 `failed/` 并写错误说明。
- 后台状态、PID 和日志保留在本机且有边界。

## 非目标

- 不调用 LLM，不上传 PDF，不做语义改写或事实纠错。
- 不保证 OCR 文本等同原稿，也不重绘复杂公式/矢量图。
- 不保存 PDF 密码，不绕过受保护文件。
- 不提供多用户队列、远程 API 或系统级 launchd 服务。

## 约束与假设

- 当前用户会话已获得项目目录的文件访问权。
- LiteParse、Poppler、Tesseract 与所需语言数据由本机提供。
- 所有 PDF 派生文本、链接和 HTML 都是不可信输入，渲染必须转义并拒绝危险 URL scheme。
- 输出必须先写临时文件，全部成功后再原子发布。
- 用户 PDF、识别结果、日志和运行状态默认不进入 Git。

## 验收标准

- 单元测试覆盖路径约束、稳定等待、原子发布、渲染转义、重排和表格修复。
- 无敏感信息的小 PDF 完成 `inbox → processing → processed + outbox` 闭环。
- HTML 可离线打开，Markdown 引用的资源路径可解析。
- 失败样本进入 `failed/` 且原文件和错误说明都保留。
- 日志按配置轮转，重复同名文件不覆盖历史结果。
